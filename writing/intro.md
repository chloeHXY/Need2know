# benchmark 的动机
与传统 PII 检测或脱敏数据集不同，我们关注的是用户与 LLM 交互中的上下文过度披露。一个敏感属性是否应该被保留，不仅取决于它是否敏感，更取决于它是否对完成当前任务是必要的。因此，我们构建了一个面向 contextual privacy 的 benchmark，用于评估模型能否区分任务必要信息与非必要敏感信息，并在保留任务效用的同时改写用户 prompt。

# 我们的数据由三层组成
第一层是半合成数据，也是当前用于训练的主要部分。
- 概述：我们采用反向合成策略：先采样 domain、task、subject、敏感属性及其 essential / non-essential 标签，再让生成模型将这些属性自然嵌入用户 prompt 中。随后使用独立 judge 反向验证生成 prompt 中的属性必要性是否与预设标签一致，只有通过一致性筛选的样本进入训练集。
- 项目路径：/group/40047/eiraxyhuang/workspace/fc/DataG/writing/layer1_reverse_synthesis

第二层是医学领域数据。
- 概述：除了通用 benchmark，我们进一步构建医学挑战集，用于压力测试模型的过度删除问题。医学 prompt 的特殊性在于，敏感信息往往同时也是任务核心信息。一个简单删除所有健康相关内容的隐私改写器可能获得较高的隐私分数，却严重损害任务效用。因此，该挑战集重点评估模型能否在保留医学任务关键信息的同时，抑制附带性私人信息泄露。我们从具有明确医学任务目标的用户 query 出发，向其中注入受控的、与医学任务无直接关系的私人信息，例如姓名、具体地点、家庭成员身份、雇主名称或偶然生活背景。这样可以检验模型是否能在保留医学任务关键信息的同时，减少附带性的隐私暴露。
